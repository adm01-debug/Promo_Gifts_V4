# Dossiê PR-3251

**Veredito:** NAO_MERGEAR

**Título:** cron.unschedule sem EXCEPTION handler

## Quatro perguntas

1. **Ainda é válida?** Sim — desagendamento de cron é operação necessária.
2. **Traz regressão?** Sim — `cron.unschedule` sem `BEGIN EXCEPTION WHEN undefined_object THEN NULL END` não é idempotente: falha se o job não existir.
3. **Já implementada no main?** Não verificado.
4. **Regra de negócio correta?** Não — mandato exige idempotência em toda migration.

## Decisão

Não mergear. Migration não idempotente: `cron.unschedule` sem handler EXCEPTION falha em reaplicação.
Fix necessário: envolver em bloco `DO $$ BEGIN cron.unschedule(...); EXCEPTION WHEN OTHERS THEN NULL; END $$;`
