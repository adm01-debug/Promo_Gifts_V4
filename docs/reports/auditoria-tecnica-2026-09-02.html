Sistema acima da média de mercado para uma operação 1-dev. CI/CD e suíte de testes são destaques absolutos — difíceis de encontrar neste porte. Os gaps que bloqueiam o 9+ concentram em: observabilidade distribuída, CSP sem unsafe-inline, feature flags e noUnusedLocals.

Fase 1 — Análise das 20 Dimensões
01 Arquitetura Alto ×2 7.5 / 10 ▶

Positivo

  • Feature-based src/: components, services, hooks, lib, types, contexts, pages, stores, routes — divisão clara
  • Arquitetura Medallion Bronze→Silver→Gold no Supabase, separação de dados explícita
  • ADRs documentados: ADR_BITRIX_SYNC, ADR_BUNDLE_BASELINE, ADR_OBSERVABILIDADE_EDGE
  • 107 edge functions como camada backend — frontend nunca toca o banco diretamente
  • src/logic/ separado para regras de negócio isoladas
  • Services layer: quoteService, productService, orderService, authService

Gaps

  • Graphify reporta 33.090 nós / 40.457 arestas — acoplamento elevado para o tamanho
  • God nodes identificados: MagazineEditorPage.tsx, QuoteItemsTable.tsx, ProductCard.tsx
  • Sem boundary explícito de domínio (DDD) — módulos de catálogo, cotação e estoque compartilham camadas
  • Sem dependency-graph automatizado para detectar ciclos de import (check:chunk-cycles existe mas manual)

Para chegar a 10/10

Quebrar os 3 god components identificados pelo Graphify (cada um em sub-componentes ≤ 200 linhas). Adicionar boundary explícito de domínio com barrel index.ts por módulo. Habilitar check:chunk-cycles como gate de CI. Documentar o grafo de dependências de módulos no ADR.

02 Autenticação Crítico ×3 8.0 / 10 ▶

Positivo

  • Supabase Auth com JWT e refresh automático
  • MFA/2FA implementado: useAuthMFA.ts com AAL1/AAL2 e step-up-verify edge function
  • Rate limiting via check-login edge function
  • Audit trail: log-login-attempt edge function
  • Detecção de novo dispositivo: detect-new-device edge function
  • auth-fuzz-weekly.yml — fuzzing semanal do fluxo de auth
  • auth-stability.spec.ts + auth-session-recovery.spec.ts em E2E
  • Logging estruturado em todo fluxo de auth via createClientLogger('auth.*')

Gaps

  • MFA disponível mas não enforçado para roles administrativos — hasMFA: false é estado válido para admins
  • Password policy: delegada ao Supabase sem documentação explícita dos parâmetros configurados
  • Logout server-side: Supabase invalida o token mas não há revogação de sessões concorrentes visível

Para chegar a 10/10

Enforce MFA obrigatório para roles admin e editor (verificar AAL no middleware de rota, não apenas disponibilizar). Documentar policy de senha no Supabase dashboard e no SECURITY.md. Adicionar endpoint de revogação de todas as sessões ativas do usuário.

06 Data Integrity Crítico ×3 7.5 / 10 ▶

Positivo

  • NUMERIC(12,2) para preços — sem risco de arredondamento float em cálculos financeiros
  • Zod em 63 arquivos — validação runtime em inputs críticos
  • RLS garante integridade de acesso a nível de linha
  • Constraints explícitas: SKU único, is_deleted hardening, NOT NULL nas colunas críticas
  • Padrão upsert com constraint UNIQUE para deduplicação em ingestões
  • UTF-8 em todo o pipeline

Gaps

  • Transações atômicas multi-tabela: sem evidência de BEGIN/COMMIT explícito no service layer — operações de quote podem ser parcialmente aplicadas
  • Optimistic locking: sem versioning/ETag em cart e quote — race conditions possíveis em edição simultânea
  • Política de soft delete vs hard delete não documentada — mistura de is_deleted e DELETE real
  • Idempotência de webhooks: não evidenciada (retry pode duplicar dados)

Para chegar a 10/10

Encapsular operações multi-tabela (quote + items + personalization) em funções PG com transação explícita. Adicionar coluna version INTEGER nas tabelas de quote/cart e validar no UPDATE (optimistic lock). Documentar política de soft delete no CLAUDE.md. Adicionar idempotency_key em endpoints de webhook.
